```text

vs

```

- Box Precision / Recall；
- Box mAP50 / mAP50-95；

- Pose mAP50 / mAP50-95；
- Depth 通道是否被网络真实利用；
- 同主体测试与跨受试者测试之间的泛化差异。

# 5. 第一次发现关键点异常

真正的问题来自对 test 预测结果的可视化检查。

在 12 张 test 图中发现极端现象：

```text
预测点看起来落在正确穴位附近，
但 GT 中 K2 / K3 对调。
```

进一步检查后发现：

> 问题不是模型完全预测错，而是 GT 的关键点 ID 定义发生了 swap。

随后对旧 81 张 label 做完整审计。

# 6. Pose Label Order Audit

新增工具：

```text
YJJ_Pose_Scripts/06_debug/check_pose_label_order.py
```

功能：

- 递归读取 YOLO Pose label；
- 根据 bbox 内相对几何模板检查关键点；
- 尝试单 pair swap；
- 标记可能显著改善一致性的 label；
- 只读分析，不修改原 label。

旧 81 张审计结果：

```text
valid       = 81
suspects    = 24
parse_error = 0
```

其中主要是：

```text
22 张：强 K2 <-> K3 swap
2 张：较弱 K5 <-> K6 swap
```

这一步确认：

> 旧数据集不是“少量随机噪声”，而是存在稳定 ID 传播 / 参考点赋值导致的系统性 label order 问题。

---

# 7. 问题定位：Stable ID 链路

随后顺着 LaMa / Pose 标注链路检查：

```text
SetRef
→ Reference canonical IDs
→ A / predict
→ current_prediction
→ Q
→ MaskLabelService.make_label
→ assign IDs
→ ordered_points
→ label txt
```

最终 writer 本身没有重新排序。

真正风险在于：

> 当前帧的点一旦继承了错误 ID，后面的 writer 会忠实把错误 ID 写进 label。

也就是说：

```text
Stable ID ≠ 正确语义 ID
```

Stable-ID 只能保证“同一个 ID 一直稳定”，不能保证这个 ID 从一开始就是正确穴位语义。

# 8. Stable-ID / Reference Geometry 修复

随后对 LaMa / Pose 标注链路做了较大修复：

- 关键点数量从固定 7 改为 UI 可配置；
- SetRef 后锁定当前 N；
- Stable-ID geometry 支持任意 N；
- shape signature；
- 自实现 Hungarian；
- similarity ICP；
- Umeyama similarity；
- ambiguity guard；
- 取消 factorial permutation；
- reference point 数量不一致时直接 BLOCK；
- bbox 改为 union + 比例 padding；
- GUI 关闭时清理 LaMa worker；
- dataset YAML staging path bug 一并修复。

修复后重新生成 / 标注数据。

再次 audit：

```text
valid       = 75
suspects    = 0
parse_error = 0
```

这 75 张成为后续“正确数据集”的基础。

# 9. Dataset YAML 临时目录坑

数据集准备过程中还遇到一个非常关键的问题：

训练时报：

```text
.prepare_pose_rgbd_tmp
```

路径仍然残留在最终 YAML 中。

表现为：

```text
data_rgb.yaml / data_rgbd.yaml
```

虽然文件被移动到了正式 dataset 目录，但 YAML 的 `path:` 仍然指向 staging：

```text
...\.prepare_pose_rgbd_tmp\dataset\...
```

导致训练无法找到 images/val。

最终修复方式：

> staging 阶段写 YAML 时就传入最终正式目录，publish 后再验证 YAML 中不允许出现任何 `.prepare_*`。

这个问题后来也成为 Cross-subject rebuild 原子发布设计的重要经验。

# 12. Corrected Core-4 Depth Ablation

随后在修正后的 RGB-D 模型上重新执行核心四组 Depth Ablation。

结果：

| Variant | Box mAP50-95 | Pose mAP50-95 |
|---|---:|---:|
| True Depth | 0.9612 | 0.9882 |
| Zero Depth | 0.8955 | 0.9950 |

| Spatial-shuffled | 0.3026 | 0.1348 |

## True vs Zero

```text
Box:

```

说明第四通道并非被网络忽略。

## Spatial Shuffle

```text
Box:

Pose:
0.9882 -> 0.1348
```

说明网络高度依赖 Depth 的空间结构。

但必须谨慎解释：

> Spatial shuffle 是强 OOD 干预，它能说明模型确实利用了 Depth 空间组织，但不能单独等价为“模型已经学到通用 3D 几何”。

# 13. 为什么必须做 Cross-subject

修正后的 12 张 test 有明显 ceiling：

```text
RGB Pose  = 0.9950
RGBD Pose = 0.9882
```

而且 test 仍然来自同主体连续数据。

因此继续在这 12 张上反复消融，很难证明真正的泛化能力。

于是测试策略改为：

```text
Subject A:
Train + Val

Subject B / C / D:
Test only
```

禁止 subject leakage。

# 16. Cross-subject 的第二个大坑：整组 ID 定义不同

拿新 Subject 第一张 label 和旧训练体系 label 对比后发现：

新数据不是随机 swap，而是整批使用了另一套固定 K 顺序。

最终 audit 的最常见 mapping：

```text
K0 <- K1
K1 <- K0
K2 <- K2
K3 <- K4
K4 <- K3
K5 <- K5
K6 <- K6
```

也就是：

```text
K0 / K1
K3 / K4
```

相对于旧训练体系发生了整体 permutation。

# 19. 当前 Cross-subject 真实结论

差值：

```text
RGBD - RGB

Box mAP50-95  = -0.0565
Pose mAP50-95 = -0.0740
```

当前 101 张跨受试者 test 上，严格 mAP50-95：

```text
RGB > RGB-D
```

但 RGB-D 同时表现出：

```text
Box Recall:
0.9531 > 0.8911

Box mAP50:
0.9497 > 0.9177
```

所以更准确的结论是：

> RGB-D 在当前新 Subject 上提高了目标召回率和较宽松 IoU 下的检测能力，但严格 Box 定位和 Pose mAP50-95 仍低于 RGB。

# 20. 最终确认的标注策略

这次 Cross-subject 的 label order 问题说明：

> 不能让每个 Subject 的第一帧通过 `(y,x)` 等自动规则重新定义 K0~K6。

未来推荐：

```text
每一组 / 每个 Subject
        ↓
第一张 Reference
        ↓
人工明确指定 K0, K1, ..., K6
        ↓
锁定 canonical ID
        ↓
后续所有帧只做 Stable-ID 继承
```

如果有 10 组：

```text
Group 1：人工定义一次
Group 2：人工定义一次
...
Group 10：人工定义一次
```

这样从源头避免事后 canonical reorder。

自动 reorder 以后只作为：

```text
历史数据修复
audit
兜底
```

而不是新数据的主标注方案。

# 21. 当前最重要的踩坑总结

## 坑 1：同主体连续帧容易制造虚高结果

12 张 test 很容易出现 Pose ceiling。

解决：

```text
增加 Cross-subject benchmark
```

---

## 坑 2：Stable ID 不等于 Semantic ID

ID 很稳定，并不能证明 K0 就真的是预期穴位。

解决：

```text
第一帧人工定义 canonical ID
```

---

## 坑 3：只看 mAP 不检查可视化会错过 GT 问题

早期如果只看数字，很难发现 K2/K3 swap。

解决：

```text
训练后必须做 prediction + GT 可视化检查
```

---

## 坑 4：自动排序规则可能在不同 Subject 上改变语义

例如 `(y,x)` 排序在手型、姿态改变后可能生成新的 permutation。

解决：

```text
不再用自动几何排序定义第一帧语义
```

---

## 坑 5：Dataset staging path 可能泄漏到最终 YAML

`.prepare_pose_rgbd_tmp` 曾进入正式 YAML。

解决：

```text
staging 时就写最终 path
publish 后再次验证
```

---

## 坑 6：Spatial Shuffle 很强，但不能过度解释

它可以说明：

```text
Depth 空间结构被模型利用
```

但不能直接写成：

```text
证明模型理解了通用 3D 几何
```

---

## 坑 7：不能为了“RGB-D 必须更好”筛选结果

当前 Cross-subject mAP50-95 明确：

```text
RGB > RGB-D
```

这必须如实保留。

真正应该做的是增加更合理、更严格的实验，检查 RGB-D 在什么条件下具有稳定优势。

# 23. 当前阶段结论

截至目前可以比较有把握地说：

1. RGB-D 第四通道确实被模型使用；
2. Depth 的空间组织对模型非常重要；
3. 同主体 test 存在明显 ceiling；
4. 标签 ID 语义一致性比单纯坐标正确更加重要；
5. 当前单一 Cross-subject 严格 mAP50-95 下 RGB 优于 RGB-D；
6. RGB-D 在 Box Recall / mAP50 上仍表现出潜在优势；
7. 后续需要扩大 Subject 数量，而不是继续在单一 test 上调结论。

# 25. 后续原则

后续所有实验继续遵守：

```text
同 split
同 labels
同 seed
同 imgsz
同 batch
同训练策略
```
