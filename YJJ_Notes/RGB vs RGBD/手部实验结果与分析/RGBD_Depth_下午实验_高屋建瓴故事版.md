# RGBD Depth 下午实验：从“模型有没有用 Depth”到“模型到底怎么用 Depth”

> 这份文档不是实验流水账，而是把今天下午所有测试重新压成一条“人能看懂的故事线”。
>
> 目标只有一个：**弄清楚第 4 通道 Depth 到底有没有被模型利用、利用了什么、为什么 RGBD Pose 没有稳定超过 RGB，以及下一步还能怎么优化。**

---

# 0. 先回答最重要的问题

## 我们是不是已经证明“数据集怎么优化都没用了”？

**不是。完全没有。**

今天真正证明的是：

> **单纯把已经映射好的 Depth 从 `1~255` 整体乘 `0.25`，再重新训练一次，并没有带来明确收益。**

这只否定了一个很具体的方案：

```text
原始 Depth 编码
1~255
    ↓
全部简单缩小到
1~64
```

它没有否定：

- 改进 Depth 的表示方式；
- 改进数据采集方式；
- 改进 train/val/test 划分；
- 让模型更多关注“相对几何”而不是“绝对深度值”；
- 对 Depth 单独做训练增强；
- 把 valid mask 与真实 Depth 分开表达；
- 增加更多距离、角度、人物和序列的数据。

所以今天不是走到死胡同。

相反，我们已经从：

> “RGBD 为什么没有简单碾压 RGB？”

走到了一个更具体的问题：

> **模型确实会用 Depth，但它同时学了真实几何、Depth 数值尺度、valid mask 等多种东西，而且这些因素会互相影响。**

---

# 1. 把模型想象成一个学生

为了容易理解，可以把 RGBD 模型想成一个学生。

RGB 模型只有三本教材：

```text
R
G
B
```

RGBD 模型多发了一本：

```text
Depth
```

我们最开始的问题非常简单：

> “这个学生到底有没有看第四本书？”

然后后面的所有实验，其实都是不断把第四本书改掉一部分，看学生考试成绩怎么变化。

---

# 2. 测试一：模型到底有没有看 Depth？

## 问题

如果把真实 Depth 全部清零，模型结果会不会变化？

## 测试

```text
True Depth
vs
Zero Depth
```

结果：

| 输入 | Box mAP50-95 | Pose mAP50-95 |
|---|---:|---:|
| True Depth | 0.9478 | 0.9349 |
| Zero Depth | 0.9330 | 0.9490 |

## 结论

✅ **第 4 通道确实会影响模型。**

但同时出现了第一个怪现象：

```text
True Depth
Pose = 0.9349

Zero Depth
Pose = 0.9490
```

也就是：

> **有真实 Depth，Pose 反而比把 Depth 清零更低。**

于是我们的真正问题变成：

> “模型到底从 Depth 里学了什么？”

---

# 3. 测试二：模型是不是只看 Depth 的平均值？

## 问题

如果 Depth 的所有像素值还在，但把它们的位置完全打乱，会怎么样？

## 测试

```text
True Depth
vs
Spatial Shuffle
```

Spatial Shuffle：

```text
Depth 数字一个不少
数值分布基本还在
但每个像素的位置被打乱
```

结果：

| 输入 | Box | Pose |
|---|---:|---:|
| True | 0.9478 | 0.9349 |
| Spatial Shuffle | 0.8699 | 0.8550 |

## 结论

✅ **模型非常在意 Depth 的空间排列。**

所以模型绝对不是只看：

```text
平均值
最大值
最小值
直方图
```

它确实在利用某种空间信息。

---

# 4. 测试三：模型在意的是很细的 Depth 纹理吗？

## 问题

如果把 Depth 平滑掉，去掉局部小变化，模型会不会变差？

## 测试

```text
Blur 11×11
Blur 31×31
Blur 51×51
```

结果全部：

```text
Box  = 0.9478
Pose = 0.9349
```

几乎与 True Depth 完全一致。

## 结论

✅ 当前模型**不太在乎这些尺度上的细小 Depth 起伏**。

所以它不像是在读：

```text
“这个像素比旁边高 2”
“那个地方突然低 1”
```

更像是在看更粗的结构。

---

# 5. 测试四：那模型是不是只看 valid mask / 轮廓？

Depth 中：

```text
0
```

不仅是一个数值。

它还代表：

> “这里没有有效 Depth。”

所以 Depth 通道里其实藏着一个天然的 mask。

---

## Flat Valid

我们把：

```text
所有 valid Depth
```

全部拍平成这张图自己的平均值。

于是只留下：

```text
valid mask
+
这张图整体平均距离
```

结果：

| 输入 | Box | Pose |
|---|---:|---:|
| True | 0.9478 | 0.9349 |
| Flat Valid | 0.9365 | 0.9303 |

## 结论

✅ **真实连续 Depth 变化本身还是有信息的。**

因为把真实高低变化抹掉以后：

```text
Box ↓
Pose ↓
```

所以不能说模型只看轮廓。

---

# 6. 测试五：每张图“整体有多远”重要吗？

我们继续把：

```text
每张图自己的平均 Depth
```

也删除。

所有图片的 valid 区域统一填：

```text
170
```

这就是：

```text
Fixed Valid
```

结果：

```text
Flat Valid
Box  0.9365
Pose 0.9303

Fixed Valid
Box  0.9365
Pose 0.9303
```

完全一样。

## 结论

在当前这批连续 Hand 图里：

✅ **“这一张手整体距离相机多远”没有表现出明显独立作用。**

但是这个结论有限制：

当前样本距离变化本来就很小。

---

# 7. 测试六：我们发现了一个真正重要的东西——Depth 的“数值大小”

这一步是下午实验的转折点。

我们干了一件很极端的事：

```text
完全不提供真实几何
完全不提供 valid mask

整张第 4 通道直接填一个常数
```

然后测试：

```text
0
1
64
128
170
224
255
```

## Pose 结果

| 常数 | Pose |
|---:|---:|
| 0 | 0.9490 |
| 1 | 0.9490 |
| 64 | 0.9490 |
| 128 | 0.9336 |
| 170 | 0.9206 |
| 224 | 0.9129 |
| 255 | 0.9080 |

这非常关键。

因为这里：

```text
没有真实 Depth
没有空间几何
只有一个数字
```

但仅仅把这个数字变大：

```text
Pose 就一路下降
```

## 结论

✅ **模型对第 4 通道的绝对数值幅度非常敏感。**

也就是说模型不只是看：

> “哪里近、哪里远。”

它还在意：

> “你给我的第 4 通道数字到底有多大。”

---

# 8. 为什么会有这个“幅度”？

我们当前的数据链：

```text
真实距离
    ↓
相机 raw depth
    ↓
1100~1850
映射到
1~255
    ↓
模型第4通道
```

所以：

> **1~255 不是物理世界天然存在的东西。**

这是我们人为设计的数据编码。

同一个真实距离，如果换一种映射方式，模型看到的数字就会改变。

这就是为什么我们开始怀疑：

> “会不会不是 Depth 本身有问题，而是 Depth 的表示尺度有问题？”

---

# 9. 测试七：真实 Depth 也缩小，Pose 会恢复吗？

于是我们不再用常数。

我们保留真实 Depth 的：

- valid mask；
- 空间位置；
- 相对高低排序；

只把数值整体缩小：

```text
25%
50%
75%
100%
```

结果：

| Depth 幅度 | 有效均值约 | Box | Pose |
|---:|---:|---:|---:|
| Zero | 0 | 0.9330 | 0.9490 |
| 25% | 42.5 | 0.9417 | 0.9490 |
| 50% | 85 | 0.9387 | 0.9405 |
| 75% | 127.5 | 0.9377 | 0.9377 |
| 100% | 170 | 0.9478 | 0.9349 |

## 结论

✅ 在原始训练好的模型上：

> **Depth 幅度越高，Pose 总体越低。**

尤其：

```text
25% Pose = 0.9490
```

已经恢复到 Zero Depth 水平。

所以当时我们一度非常怀疑：

> “是不是原始 Depth 幅度太大？”

---

# 10. 测试八：25% 恢复，是因为“几何有用”还是因为“幅度变小”？

这个问题必须继续拆。

我们做：

```text
Scaled True 25%
```

它有：

```text
低幅度
+
真实空间变化
```

再做：

```text
Flat Scaled 25%
```

它有：

```text
同样低幅度
+
同样 valid mask
+
没有真实空间变化
```

结果：

```text
Scaled True 25%
Box  0.9417
Pose 0.9490

Flat Scaled 25%
Box  0.9417
Pose 0.9490
```

完全一样。

## 结论

✅ 25% 时 Pose 恢复到 0.9490，主要是：

> **高幅度负作用消失了。**

而不是：

> “低幅度以后真实几何突然给 Pose 带来了额外收益。”

但在 50%、75%、100% 条件下，真实几何有时又能产生小幅正收益。

所以：

> **几何有没有用，不是固定答案，它和当前 Depth 幅度存在交互。**

---

# 11. 测试九：我们的 Hand 数据是不是刚好 test 特别“高幅度”？

这时我们不能只盯 12 张 test。

于是扫描完整：

```text
train 57
val   12
test  12
共 81 张
```

原始有效 Depth：

| Split | Pixel Mean | P50 |
|---|---:|---:|
| train | 180.85 | 226 |
| val | 175.17 | 225 |
| test | 169.96 | 224 |

## 结论

✅ **高幅度不是 test 偶然现象。**

整个 Hand 数据集大量有效 Depth 都集中在：

```text
224~243
```

附近。

所以“幅度问题”值得真正拿到训练阶段验证。

---

# 12. 测试十：真正把训练数据改成 Scale25，再从头训练

这是最重要的一步。

因为之前都是：

```text
原模型训练完
→ 测试时临时改 Depth
```

这不能证明：

> “训练阶段就用 Scale25 会更好。”

所以我们真正生成了一套新数据：

```text
rgbd_rawdepth_scale25
```

把：

```text
1~255
```

压成约：

```text
1~64
```

同时保持：

```text
RGB 不变
label 不变
split 不变
valid mask 不变
```

然后从同一个干净 4ch 初始权重重新训练。

# 13. 真正公平的最终结果

| 模型 | Box | Pose |
|---|---:|---:|
| RGB baseline | **0.9723** | 0.8958 |
| Raw RGBD | 0.9478 | 0.9349 |
| Scale25 RGBD | 0.9464 | **0.9375** |

Scale25 相比 Raw RGBD：

```text
Box  -0.0013
Pose +0.0026
```

## 结论

❌ 不能说 Scale25 明显更好。

因为：

```text
只有 12 张 test
只训练了一次
只有一个 seed
差异只有 0.0026
```

更合理的判断：

> **Raw RGBD 与 Scale25 RGBD 基本处于同一水平。**

# 14. 最后的 Cross-Scale 实验

我们又补了最后一个 2×2：

| Train | Raw Test Pose | Scale25 Test Pose |
|---|---:|---:|
| Raw-trained | 0.9349 | **0.9490** |
| Scale25-trained | 0.9348 | 0.9375 |

Box：

| Train | Raw Test Box | Scale25 Test Box |
|---|---:|---:|
| Raw-trained | 0.9478 | 0.9417 |
| Scale25-trained | 0.9417 | 0.9464 |

## Box 告诉我们

✅ 网络会适应训练时的 Depth 数值尺度。

```text
Raw 模型
→ 更喜欢 Raw test

Scale25 模型
→ 更喜欢 Scale25 test
```

## Pose 告诉我们

Pose 更复杂。

Raw 模型临时看到 Scale25：

```text
0.9490
```

非常高。

但 Scale25 真正重新训练后：

```text
0.9375
```

这个巨大提升没有保留下来。

所以：

> **推理时“改输入”看到的收益，不能直接等价成“这种数据编码适合重新训练”。**

---

# 15. 今天下午到底得到了什么？

把所有实验压成一句话：

> **模型确实学会并利用了 Depth，但它利用的不只是“真实三维几何”。它同时会响应 Depth 的空间结构、valid mask、绝对数值尺度，而且这些因素之间会互相作用；训练过程还会重新适应 Depth 的表示尺度。**

所以我们现在不能说：

```text
Depth 没用
```

也不能说：

```text
Depth 数值太大就是罪魁祸首
```

更不能说：

```text
Scale25 就是最佳方案
```

---

# 16. 我们已经明确知道的 5 件事

## ① Depth 确实被模型使用

✅ True / Zero 不一样。

## ② Depth 空间结构确实重要

✅ Spatial Shuffle 大幅崩掉。

## ③ Depth 的细小局部纹理不是当前主要信息

✅ Blur 11/31/51 几乎完全不影响。

## ④ Depth 的绝对数值尺度确实影响模型

✅ Constant Sweep 和 Scaled True 都证明了。

## ⑤ 模型训练后会适应新的 Depth 尺度

✅ Scale25 重新训练 + Cross-Scale Box 清楚证明了。

---

# 17. 但我们还不知道的 4 件事

## ① 什么样的 Depth 表示方式最适合 Pose？

不知道。

今天只验证了：

```text
原始线性映射
vs
简单 ×0.25
```

还远远没有覆盖所有可能。

## ② RGBD 为什么 Box 比 RGB 低，而 Pose 比 RGB 高？

目前只知道这是稳定现象之一。

但还没有完全解释网络内部为什么会形成这种任务分工。

## ③ Depth 真正最有用的是哪类几何？

目前只知道：

```text
空间排列有用
真实连续变化有时有用
细小高频变化不重要
```

还不知道是：

- 手掌整体起伏；
- 前后关系；
- 局部曲面；
- 深度边界；
- 身体轮廓；

哪一个最关键。

## ④ 这些结论能不能推广？

目前还不能。

因为现在：

```text
Hand 总共 81 张
test 只有 12 张
而且很多是连续帧
```

---

# 18. 所以“优化数据”还有没有路？

**有，而且现在反而比下午开始时更知道该优化什么。**

---

## 路线 A：先优化“数据多样性”

这是优先级最高的。

现在最明显的问题不是模型太弱，而是：

```text
81 张
+
连续帧很多
+
距离范围相对集中
```

下一批数据应该主动增加：

- 不同人与不同手；
- 不同相机距离；
- 不同角度；
- 不同姿态；
- 不同背景；
- 不同采集时间段；
- train / val / test 按序列隔离，而不是相邻帧随机拆分。

目的：

> 让模型不能靠“这一小段视频里的固定规律”取巧。

---

## 路线 B：不要简单缩放 Depth，而是突出“相对几何”

今天的结果已经提示：

> 绝对 Depth 幅度会影响模型。

那么一个更合理的思路是：

```text
不让模型太依赖
“这只手总体是 170 还是 220”

而让它更关注
“手内部哪里比哪里近/远”
```

例如未来可以研究：

```text
每张图 / 每个 ROI 的相对 Depth
```

概念上：

```text
Depth - 当前手区域的中位数
```

再重新编码。

这样：

```text
整体距离
```

被弱化，

而：

```text
手表面相对高低
```

被突出。

这比简单：

```text
全部 ×0.25
```

更有针对性。

---

## 路线 C：训练时专门给 Depth 做幅度增强

现在模型明显会适应一个固定尺度。

那可以反过来：

> 不让它习惯固定尺度。

例如训练时随机：

```text
Depth × 0.5
Depth × 0.8
Depth × 1.0
Depth × 1.2
```

只对 valid Depth 做，invalid 仍保持 0。

目标：

> 逼模型少依赖绝对幅度，多依赖空间关系。

这其实是今天实验非常自然导出的方向。

---

## 路线 D：把“valid mask”和“真实 Depth”分开

当前第 4 通道同时承担：

```text
0 / 非0
→ valid mask

非0的具体数值
→ Depth
```

网络必须自己把这两种语义分开。

未来如果架构允许，可以尝试：

```text
RGB + Depth + ValidMask
```

也就是 5 通道。

这样：

```text
Depth
```

只负责几何，

```text
Mask
```

单独告诉模型哪里有效。

这已经不是纯数据集优化，而是输入表示设计。

---

# 19. 如果我们现在继续，我建议的优先级

不要马上再造一堆 Scale10、Scale50。

推荐顺序：

```text
第一优先：
增加更有多样性的 Hand 数据
+
重新设计 sequence-level train/val/test

第二优先：
验证“相对 Depth / ROI-centered Depth”

第三优先：
Depth-only amplitude augmentation

第四优先：
如果还需要，再考虑 Depth + ValidMask 分通道
```

---

# 20. 今天真正最值钱的结论

下午开始时我们问：

> “RGBD 为什么没有简单超过 RGB？是不是 Depth 没学会？”

现在答案已经变成：

> **不是。Depth 学了，而且模型确实会用。问题是它同时学了很多我们原本没意识到的东西，包括 Depth 的数值尺度。真正需要优化的，不是简单决定‘用不用 Depth’，而是决定‘应该把什么样的 Depth 信息，以什么方式交给网络’。**

这就是今天整条实验线最重要的收获。
