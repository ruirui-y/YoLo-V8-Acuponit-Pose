与原总纲的关系：原方向 2（不同网络模型）与原方向 3（YOLO 版本 4 通道）在本方向内**合并成一条线**，拆成两段执行：

| 阶段 | 内容 | 状态 |
|---|---|---|
| **上半段** | 在 **RGB 3 通道** 上比较 YOLO 版本 | **已完成**（2026-10-10） |
| **下半段** | 把胜出方案改造成 **4 通道 RGBD**，与第一阶段 RGBD 基线对比 | 待进行 |

## 3. 模型选型依据

**不是主观挑选，而是由官方权重供给决定的。** 2026-10-10 实测 GitHub `ultralytics/assets` 的 `v8.4.0` release，`-pose.pt` 权重只有三代：

| 权重族 | 是否存在 |
|---|---|
| `yolov8{n,s,m,l,x}-pose.pt` | ✅ |
| `yolo11{n,s,m,l,x}-pose.pt` | ✅ |
| `yolo26{n,s,m,l,x}-pose.pt` | ✅ |
| `yolo12*-pose.pt` | ❌ **不存在** |

**最终入选三代**（统一 n 规模）：

| 编号 | 模型 | 权重 | 架构关键差异 |
|---|---|---|---|
| M1 | YOLOv8 | `yolov8n-pose.pt` | C2f + DFL（`reg_max=16`）+ NMS 后处理 |
| M2 | YOLO11 | `yolo11n-pose.pt` | C3k2 + C2PSA（注意力）+ DFL + NMS |
| M3 | YOLO26 | `yolo26n-pose.pt` | **无 DFL（`reg_max=1`）** + 端到端双头结构 |

排除清单：

| 候选 | 排除原因 |
|---|---|
| YOLOv5 | 从未有官方 pose 变体（仅 detect/seg/cls） |
| YOLOv9 / YOLOv10 | ultralytics 未提供 pose 配置与权重 |
| YOLOv13 | ultralytics 未收录 |
| RT-DETR | 有 detect，无 pose |
| YOLOv12 | **无官方 pose 预训练权重**，只能由 detect 权重迁移，pose head 随机初始化，与另外三代「COCO-pose 全量预训练」不对等 |
| `yolov8n-pose-p6` | 1280 高分辨率设定，与 640 不同级 |

**规模统一取 n 的理由**：与第一阶段 RGB 基线同为 n，可直接对照；训练集仅 52 张，s/m 规模易过拟合。

## 6. 控制变量

三个版本**唯一允许不同的只有「用哪个权重开头」**。其余全部取自第一阶段 RGB 基线
（`yolov8_rgbd_detection\runs\pose\train_pose_rgb_3ch5\args.yaml`）：

| 项 | 值 | 项 | 值 |
|---|---|---|---|
| epochs | 120 | mosaic / mixup / copy_paste | 0 / 0 / 0 |
| patience | 20 | fliplr / flipud | 0 / 0 |
| batch | 4 | degrees / translate / scale | 10 / 0.1 / 0.2 |
| imgsz | 640 | shear / perspective | 0 / 0 |
| device | `0` | hsv_h / hsv_s / hsv_v | 0 / 0 / 0 |
| workers | 0 | optimizer | auto |
| cache / amp | False / False | seed / deterministic | 0 / True |
| close_mosaic | 10 | cos_lr | False |
| fraction | 1.0 | pretrained / val | True / True |

> ⚠️ **记录值 ≠ 生效值**：`optimizer=auto` 会让 ultralytics **忽略 `lr0=0.0005`**，自动选择
> `AdamW(lr=0.002, momentum=0.9)`。第一阶段同为 `auto`，因此三代之间仍然一致；
> 若将来需要精确复现，应显式写 `optimizer=AdamW, lr0=0.002`。

**「17 点 → 7 点」换头是自动的**：权重自带 COCO 17 点，训练时 ultralytics 依 `data_rgb.yaml` 的
`kpt_shape=[7,3]` 重建 pose head。日志证据：

```text
Overriding model.yaml kpt_shape=[17, 3] with kpt_shape=[7, 3]
```

**中间验证（正式训练前）**：

1. 三代权重加载验证 → 全部 `task=pose`、`kpt_shape=[17,3]`。
2. 推理结构一致性 → 三代输出均为 `boxes.xyxy (1,4)` / `kpts.xy (1,17,2)` / `kpts.conf (1,17)`，可用同一套后处理。
3. 冒烟训练（1 轮 × 3 版本）→ 全部通过，训练后权重 `kpt_shape` 为 `[7,3]`。

## 7. 主评价指标

### 7.1 Cross-subject coverage

记录 `Total` / `Matched` / `Match rate`；多模型比较时额外记录 **Common matched**（所有模型共同命中的图片）。

### 7.2 NME

与方向 1 完全一致的定义：

- GT bbox diagonal 归一化
- 只统计 `visibility > 0` 的关键点
- `bbox IoU >= 0.50` 才算 matched

### 7.3 单关键点像素误差

记录 `K0 ~ K6` 的 mean px（本阶段实现到 mean px 一级）。

### 7.4 标准 Pose 指标

如框架支持，统一记录 Box / Pose 的 mAP50、mAP50-95。

### 7.5 效率

- Params / FLOPs
- 单图推理耗时（含预处理与后处理）

## 8. 评估口径实现

**算法唯一来源**：直接复用第一阶段的 `YJJ_Pose_Scripts\04_eval\eval_rgb_vs_rgbd_nme.py`，
**不重写实现**。`MultiYoloRGB\eval_versions.py` 以 import 方式复用它。

| 项 | 值 |
|---|---|
| 入口 | `MultiYoloRGB\eval_versions.py` |
| 推理 conf / imgsz | 0.001 / 640 |
| matched | 预测框与 GT 框 **IoU ≥ 0.50**（取 IoU 最大的预测实例） |
| NME | 每个可见关键点 `像素误差 ÷ GT框对角线`，再取平均 |
| 像素误差 | `sqrt((pred_x-gt_x)² + (pred_y-gt_y)²)` |
| 公平比较集 | **三模型共同命中的图片** |

```cmd
cd /d H:\YJJ\Yolo_RGBD\MultiYoloRGB
.venv\Scripts\python.exe eval_versions.py
```

> ⚠️ **import 顺序陷阱（已处理）**：第一阶段脚本顶部会执行 `sys.path.insert(0, 项目根)`，
> 其中包含 vendored `ultralytics 8.3.176`。若顺序颠倒，venv 的 8.4.175 会被顶掉、
> YOLO26 直接加载失败。正确顺序：**先锁定 8.4.175 → 再 import 第一阶段模块 →
> 移除泄漏路径 → 复核版本未被替换**。

## 9. 结果判定原则

不能只看一项 mAP / NME。优先顺序：

1. Cross-subject 是否稳定 matched
2. Common matched 上的 NME
3. `K0~K6` 是否存在结构性弱点
4. Pose mAP
5. 参数量与速度

如果一个模型 mAP 高，但 Cross-subject NME 或 coverage 明显更差，不能直接判定它更适合当前任务。
