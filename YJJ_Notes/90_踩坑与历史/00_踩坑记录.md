# 踩坑记录

本文件只记录会影响实验可信度或复现结果的问题。

---

## 1. 关键点 Stable ID 不等于 Semantic ID

早期最严重的问题是：

标签内部 K0~K6 的编号可以保持“稳定”，但稳定并不代表这些编号在不同数据批次中代表相同的穴位语义。

曾出现预测图看起来“点位置大致合理”，但与 GT 对应 ID 错位的情况。

结论：

**任何新数据进入正式训练/测试前，都必须先检查关键点语义顺序。**

---

## 2. 旧 Hand 标签顺序错误导致早期结果失效

旧数据经过 label-order audit 后发现问题。

修复后：

```text
valid   = 75
suspect = 0
parse_error = 0
```

因此更早的 81 张数据和错误 keypoint order 实验不能作为当前最终结论。

---

## 3. Cross-subject 整批使用另一套固定 K 顺序

外部 101 张测试图第一次评估曾出现 Pose 接近 0 的异常。

后来发现不是随机 swap，而是整批固定 permutation：

```text
K0 <- K1
K1 <- K0
K2 <- K2
K3 <- K4
K4 <- K3
K5 <- K5
K6 <- K6
```

Canonical audit：

- 101 / 101 主 mapping 一致
- Max residual 约 0.1642
- Blocked 0

重排后 Pose 恢复正常。

结论：

**新 Subject 必须先做 canonical 对齐，不能直接默认 K0~K6 语义一致。**

---

## 4. Dataset YAML staging path

曾出现数据集从临时 staging 目录发布到正式目录后，YAML 文件内部的 `path:` 仍然指向：

`.prepare_pose_rgbd_tmp`

或者指向移动前的旧目录。

文件虽然已经移动，Ultralytics 仍会按 YAML 的旧 path 找数据。

结论：

发布/移动数据集后必须检查：

- `data_rgb.yaml`
- `data_rgbd.yaml`

的 `path:` 是否指向最终目录。

---

## 5. Same-subject 连续帧指标虚高

修正后的 12 张 test 来自与训练相同的主体，并且存在连续时间帧。

曾得到接近 ceiling 的 Pose 指标：

- RGB Pose mAP50-95：0.9950
- RGBD Pose mAP50-95：0.9882

这类结果适合 sanity check，但不能证明跨人的泛化。

结论：

**正式主结论优先使用 Cross-subject。**

---

## 6. Depth 文件“有效”不代表适合直接训练

训练 Depth 75 / 75 都通过质量门槛，但原始数据：

`Mean hole ratio = 0.1267`

即平均约 12.67% 像素为空洞/无效。

结论：

**只看文件能否加载或整张图是否通过阈值，会掩盖局部 Depth 空洞。**

---

## 7. 无效 Depth 不只有 0

实际数据中需要统一考虑：

- 0 / 非正值
- 65535
- NaN
- Inf

如果只把 0 当无效值，65535 等异常值可能继续进入滤波或第四通道映射。

当前统一 invalid mask：

```text
(~isfinite(depth)) | (depth <= 0) | (depth == 65535)
```

---

## 8. 训练和测试 Depth 预处理必须一致

当前正式管线：

训练：

```text
session1/out_npy
-> filter
-> session1/out_npy_filtered
-> RGBD Train/Val
```

Cross-subject：

```text
session3/out_npy
-> filter
-> session3/out_npy_filtered
-> RGBD Test
```

不能一边使用 filtered Depth、另一边继续 raw Depth，却仍当成同一实验。

## 9. “RGBD NME 更低”不等于这张图就是好案例

曾按 Delta NME 排名挑出 RGBD 大胜图片，但打开可视化后发现：

- RGB 本身很差
- RGBD 也很差
- 只是 RGBD 相对少错一点

例如高绝对像素误差的图即使 `delta_nme < 0`，也不适合作为优势案例。

当前原则：

**CSV 负责全量统计，典型案例必须再做绝对误差和可视化人工检查。**

## 10. Coverage 和定位精度必须分开

NME 是：

**成功匹配条件下的定位误差。**

Matched 数量是：

**覆盖能力。**

不能只报 Common matched NME 而忽略一个模型漏掉多少图。

当前必须同时报告：

- RGB / RGBD matched
- Common
- model-only
- neither
- Common NME

---

## 11. 相对提升不能自动解释成 Depth 因果作用

修补 Depth 后当前 RGBD 结果明显改善，但修补前后同时还存在：

- 训练数据变化
- 测试第 4 通道变化
- 模型重新训练
- Common matched 集合变化

因此不能写：

> 某一个 fill/filter 操作单独造成全部提升。

当前只写：

> Depth 数据质量与预处理管线对 RGBD 表现具有重要影响。

## 12. 评估 CSV schema 需要同步维护

给 `per_image.csv` 新增 K0~K6 字段后，`rgbd_better_rows` 已经包含新字段，但旧的 `DictWriter.fieldnames` 没同步更新，导致：

```text
ValueError: dict contains fields not in fieldnames
```

后来统一了完整字段集合。

结论：

新增 CSV 字段时，所有写出分支必须共用同一 schema，避免结果已经算完却在最后保存阶段失败。

## 14. YAML 的 kpt_shape 与通道配置必须与数据一致

旧腿部实验中出现过三处 YAML 配置错误：

- 腿部标签是 10 个关键点，但 YAML 仍沿用腹部 3 点的 `kpt_shape`，
  必须改成 `kpt_shape: [10, 3]`。
- RGB 模型误用了带 `rgbd: true` 的 YAML，导致通道数不匹配（3 通道权重 + 4 通道配置）。
  RGB 与 RGBD 必须各自持有独立 YAML：
  `rgbd: false, channels: 3` 与 `rgbd: true, channels: 4`。
- 同一批图片的关键点数量不统一（旧腿部数据在 3~13 个之间）时不能混在一起训练，
  必须先按关键点数量分组，只在同一组内做实验。

结论：

**换部位 / 换关键点数量就等于换数据集配置，`kpt_shape`、通道数、标签三者必须同时对齐。**

---

## 15. 修改 YAML 或标签后必须清理 labels/*.cache

Ultralytics 会把标签解析结果缓存为 `labels/*.cache`。

修改 YAML（尤其是 `kpt_shape` / 通道数）或改动标签文件后，旧缓存不会自动失效，
训练仍会加载旧的标签信息。表现出来就是"代码和数据都改了，指标却纹丝不动"。

结论：

**每次修改 YAML 或标签后，先删除对应 `labels/*.cache` 再启动训练。**
